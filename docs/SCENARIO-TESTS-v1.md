# 特定角色 · 特定场景测试方案 v1

> 目标：验证「情报 / 产物 / 问答 / 知识 / 回顾」五条闭环在真实角色工作流里能走通，而不是只验证按钮存在。
> 数据口径：测试数据统一用 `SCENARIO-` 前缀或 `source=intel|knowledge`；测试结束必须清理。不伪造工作流运行数据。
> 关联台账：`REQ-20261120-01`、`REQ-20261120-02`

## 1. 闭环范围

| 编号 | 闭环 | 入口 | 落点 |
| --- | --- | --- | --- |
| C1 | 情报 → 计划 | 情报流「转今日计划」 | 计划页今日 |
| C2 | 工作流产物 → 知识 | 作战板「存入知识」 | 回顾 · 知识沉淀 |
| C3 | 问答 → 知识 | 回答底部「存入知识」 | 回顾 · 知识沉淀 |
| C4 | 知识 → 计划 | 知识详情「转为今日计划」 | 计划页今日 + 知识 `links` |
| C5 | 回顾 → 顺延 | 今日回顾「计划达成」顺延 | 次日 / 下周一计划 |

## 2. 测试角色

### R1 多项目产品经理 · 林一
- 数据画像：5 个项目并行，每天 3–5 条情报，会议打断 2–3 次，计划以 60–90 分钟 `phase` 为主
- 核心诉求：情报快速变任务；被打断后第二天能接上
- 重点场景：S1、S2、S6

### R2 独立开发者 · 陈默
- 数据画像：单项目长专注，工作流产出多，问答与知识沉淀多
- 核心诉求：产物 / 回答可归档，知识能变成下一步行动
- 重点场景：S3、S4、S6

### R3 备考学生 · 周舟
- 数据画像：固定时段，`task` 型计划多，周末集中复盘
- 核心诉求：本周没做完的能顺延到下周，不丢任务
- 重点场景：S5、S7

## 3. 场景矩阵

| ID | 角色 | 场景 | 前置 | 操作 | 期望 |
| --- | --- | --- | --- | --- | --- |
| S1 | 林一 | 早间情报 triage | 情报流 ≥3 条 | 情报页点第 1 条「转今日计划」→ 打开计划页今日 | 计划标题=情报标题（≤60 字）；来源显示「情报」；备注含摘要与 URL；按钮变「已加入计划」 |
| S2 | 林一 | 被打断的一天 | 今日 2 条 `phase` 计划，时间窗落在无工作时段 | 回顾 → 今日回顾 → 计划达成 → 单项「顺延」→ 批量顺延 | 原计划 `delayed`；次日生成 `planned` 副本；出现「已顺延 N 项到 …」 |
| S3 | 陈默 | 工作流交付 | 工作流节点有真实输出 | 作战板 → 任务报告 → 存入知识 → 回顾 · 知识沉淀 | `source=workflow`；`links` 指向 workflow；正文=节点输出；空输出不可点 |
| S4 | 陈默 | 问答沉淀 | 有一条助手回答 | 回答底部「存入知识」→ 知识页搜索 | `source=qa`；正文「问：… 答：…」；可检索 |
| S5 | 周舟 | 周末复盘 | 本周一至今天有 2 条未完成 `phase` 计划 | 回顾 → 本周 → 顺延到下周一 → 计划页下周一 | 原计划 `delayed`；下周一 2 条 `planned` 副本；未来日期的计划不被误顺延 |
| S6 | 跨角色 | 防重复 | 已完成上面的 S1/S3/S4 | 同一知识再点「转为今日计划」；同一情报再点；已 `done` / `delayed` 计划回看 | 知识按钮变「已关联计划」且不新增；情报按钮变「已加入计划」；回顾不出现顺延按钮 |
| S7 | 跨角色 | 空态与边界 | 无计划日 / 无情报 / 空知识 | 超长标题、无标题知识、空数据页 | 标题截断 60 字；无标题提示先补标题；空态文案正常；不产生空计划 |

## 4. 执行方式

- 手工路径 + CDP 辅助断言：`window.api.listPlans()` / `window.api.listKnowledge()` 读取真实字段
- 每个场景记录：操作前数据量 → 操作 → 目标页可见 → API 字段 → 刷新后仍在 → 清理结果
- 失败记录到 `docs/QA-ISSUES.md`，修复后回填
- 批量操作（本周顺延）只在测试前置数据上执行，避免影响真实计划
