## Part 1: 独立桌面游荡角色架构

> **核心原则**：虚拟人不是 App 窗口里的内容，而是**活在桌面上的独立存在**。她与你的壁纸、图标、其他窗口共处同一空间。

### 1.1 窗口架构变革

#### 旧架构 vs 新架构

| 维度 | 旧架构（右下角框内） | 新架构（独立游荡） |
|------|---------------------|-------------------|
| **容器** | Electron BrowserWindow 400×600 固定右下角 | Electron 透明全屏覆盖窗口，虚拟人仅占其中一小片区域 |
| **Z序** | 常驻最顶层或嵌入 App | 与桌面图标同层，可被其他窗口遮挡 |
| **移动范围** | 不可移动 | 全桌面自由移动，跨显示器 |
| **点击穿透** | 窗口整体可点击 | 仅人物轮廓区域可交互，其余完全透明穿透 |
| **遮挡关系** | 永远挡在内容上方 | 走到窗口后面会自然被遮挡 |
| **存在感** | 工具挂件 | 桌面居民 / 数字宠物 / 助理 |

#### Electron 窗口参数

```ts
// main/character-window.ts
const characterWindow = new BrowserWindow({
  width: screen.getPrimaryDisplay().bounds.width,
  height: screen.getPrimaryDisplay().bounds.height,
  x: 0,
  y: 0,

  skipTaskbar: true,
  resizable: false,

  webPreferences: {
    nodeIntegration: true,
    contextIsolation: false,
    offscreen: false,
    webgl: true,
  },
});

// 关键：设为桌面层级（Windows）
characterWindow.setFullScreenable(false);

// Windows: 使用 SetWindowPos 将窗口置于桌面图标层与窗口层之间
// 需要调用 native addon 实现
const setDesktopLayer = () => {
  const hwnd = characterWindow.getNativeWindowHandle();
  // 1 = HWND_BOTTOM 不对，需要特殊处理
  // 实际方案：找到 Progman 窗口，将本窗口作为其子窗口
  setWindowAsDesktopChild(hwnd);

```

#### 桌面层级实现方案

```
Windows 实现：
  方案A（推荐）：注入桌面窗口
    - 找到 WorkerW / Progman 窗口
    - 将 characterWindow 的 HWND 设为 WorkerW 的子窗口
    - 这样虚拟人就在壁纸层和图标层之间
    - 优点：最自然，其他窗口会遮挡她
    - 缺点：需要管理员权限一次（首次启动时），或用 SPI_SETDESKWALLPAPER 绕过

  方案B（降级）：alwaysOnTop + 点击穿透
    - characterWindow 永远置顶
    - 人物区域外 setIgnoreMouseEvents(true, {forward: true})
    - 人物区域 setIgnoreMouseEvents(false)
    - 优点：实现简单，无需管理员
    - 缺点：永远遮挡其他窗口，体验像挂件

  方案C（Mac/Linux）：
    - macOS: NSWindowLevel 设为 desktop 层级
    - Linux: 依赖 WM，使用 _NET_WM_WINDOW_TYPE_DESKTOP

推荐：Windows 用方案A，Mac 用方案C，Linux 用方案B降级。
```

### 1.2 坐标系与定位系统

#### 桌面坐标系

```
坐标系定义：
  - 原点 (0,0)：主显示器左上角
  - X 轴：向右为正
  - Y 轴：向下为正
  - 单位：像素（CSS 逻辑像素，DPI 缩放由 Three.js 自动处理）
  - Z 轴：深度，用于人物前后关系（0 = 屏幕平面，+Z 向用户凸出）

虚拟人锚点：
  - 脚底中心点为定位锚点 (x, y, 0)
  - 角色高度 200-400px（可缩放 0.5x-2.0x）
  - 头顶坐标 = 锚点 y - height × scale

缩放规则：
  - 默认 scale = 1.0（约 300px 高）
  - 最小 scale = 0.5（专注模式不打扰）
  - 最大 scale = 2.0（交互/提醒时）
  - 缩放动画：0.3s ease-out
```

#### 安全区域与边界

```
安全区域计算：
  - 全桌面可用区域 = 所有显示器并集 bounds
  - 任务栏区域 = 排除（Windows 任务栏 48px / macOS Dock 根据设置）
  - 应用窗口占据区域 = 动态检测（每 500ms 扫描一次）
  - 图标密集区 = 可配置是否避开

边界约束：
  - 硬边界：角色锚点不可超出桌面 bounds
  - 软边界：角色中心距边缘 ≥ 100px（防止半截身子在屏幕外）
  - 多显示器边界：鼠标/角色接近屏幕边缘 50px 时，触发跨屏转移

避障行为：
  - 默认：虚拟人可走到窗口下方（被遮挡）
  - 可选：开启"避开窗口"模式时，会绕过窗口边缘
  - 可选：开启"不遮挡图标"模式时，优先停留在图标空白区域
```

#### 位置状态机

```
enum CharacterPositionState {
  ROAMING,       // 自由游荡
  PINNED,        // 用户固定位置
  FOLLOW_MOUSE,  // 跟随鼠标（轻跟随，不贴太近）
  SITTING_LEDGE, // 坐在窗口边缘/任务栏
  SLEEPING,      // 缩在角落睡觉
  BLOCKING,      // 遮挡屏幕提醒模式
  PRESENTING,    // 居中展示/全局问答
}

状态切换条件：
  ROAMING → FOLLOW_MOUSE: 用户开启鼠标联动
  FOLLOW_MOUSE → ROAMING: 用户关闭或 5min 无操作
  ROAMING → SITTING_LEDGE: 检测到窗口边缘且 idle > 30s
  ROAMING → SLEEPING: 系统 idle > 10min 且不在番茄钟
  ROAMING → BLOCKING: 检测到严重摸鱼且达到遮挡阈值
  ROAMING → PRESENTING: 用户按 Cmd+K / 重要通知 / 启动仪式
  ANY → PINNED: 用户右键"固定在此"
```

### 1.3 点击穿透与命中检测

#### 像素级命中检测

```ts
// renderer/character-canvas.ts
const raycaster = new THREE.Raycaster();
const mouse = new THREE.Vector2();

const isPointerOverCharacter = (clientX: number, clientY: number): boolean => {
  // 将屏幕坐标归一化到 NDC
  mouse.x = (clientX / window.innerWidth) * 2 - 1;
  mouse.y = -(clientY / window.innerHeight) * 2 + 1;
  
  raycaster.setFromCamera(mouse, camera);
  const intersects = raycaster.intersectObjects(characterMeshGroup, true);
  
  // 只检测 opacity > 0.1 的三角面
  const validHit = intersects.find(hit => {
    const mat = hit.object.material as THREE.MeshStandardMaterial;
    return mat && mat.opacity > 0.1;
  });
  
  return !!validHit;
};

// 每帧根据鼠标位置更新窗口点击穿透
const updateClickThrough = throttle((e: MouseEvent) => {
  const overCharacter = isPointerOverCharacter(e.clientX, e.clientY);
  if (overCharacter) {
    // 取消点击穿透，允许交互
    ipcRenderer.send('set-ignore-mouse-events', false);
    document.body.style.cursor = 'pointer';
  } else {
    // 开启点击穿透，鼠标事件透传给下层桌面/窗口
    ipcRenderer.send('set-ignore-mouse-events', true, { forward: true });
    document.body.style.cursor = 'none';
  }
}, 16);
```

#### 透明区域优化

```
性能方案：
  - 全屏透明 WebGL 每帧渲染成本高
  - 优化：仅人物周围 bounding box 渲染，其他区域完全不绘制
  - 使用 scissor test 限制渲染区域
  - 静止时：渲染区域缩小到人物 bbox + 50px 边距
  - 移动/特效时：动态扩展 bbox

裁剪示例：
  gl.enable(gl.SCISSOR_TEST);
  gl.scissor(bbox.x, bbox.y, bbox.w, bbox.h);
```

### 1.4 与主 App 窗口的协作

```
窗口关系：
  - 主 App（日历/报表/规划）是独立普通窗口
  - 虚拟人窗口是桌面覆盖层
  - 两者通过 IPC / 共享状态机通信

协作行为：
  主 App 打开时：
    - 虚拟人可走到 App 窗口后方（自然被遮挡）
    - 或自动让开，坐到窗口边缘
    - 用户可设置"App打开时虚拟人行为"：避让 / 无视 / 最小化
  
  主 App 最小化时：
    - 虚拟人恢复自由游荡
  
  全局问答 (Cmd+K) 触发时：
    - 虚拟人从当前位置走到屏幕中央偏下
    - 或放大到 1.5x 进入 PRESENTING 状态
  
  番茄钟启动时：
    - 虚拟人头顶显示倒计时粒子环
    - 可坐在任务栏边缘或屏幕角落
  
  屏幕遮挡提醒时：
    - 虚拟人放大到 2.0x
    - 走到屏幕中央
    - 配合遮罩层（另一窗口）实现屏幕遮挡
```

### 1.5 游荡 AI 行为系统

#### 游荡目标点生成

```
目标点选择算法：
  1. 每 10-60s 随机选择一个新目标点
  2. 目标点必须满足：
     - 在桌面 bounds 内
     - 不在当前鼠标位置 200px 内（避免打扰操作）
     - 不在全屏窗口覆盖区域（除非开启"走到后面"）
  3. 加权随机：
     - 阳光区域（壁纸明亮处）权重 +20%
     - 靠近用户当前工作窗口处 +30%（方便观察）
     - 角落区域 +10%（人喜欢角落休息）
     - 图标空白区 +15%

路径规划：
  - 简单版：直线插值 + 边界反弹
  - 进阶版：A* 避障（绕开窗口边缘）
  - 默认使用简单版，"避开窗口"模式开启用进阶版
```

#### 游荡动画状态

```
enum RoamingAction {
  IDLE_STAND,     // 原地站立，呼吸
  IDLE_SIT,       // 坐下
  WALK_SLOW,      // 慢走
  WALK_FAST,      // 快走
  RUN,            // 小跑（紧急情况）
  TELEPORT_IN,    // 从屏幕外进入
  TELEPORT_OUT,   // 离开屏幕
  PEEK_FROM_EDGE, // 从屏幕边缘探头
  JUMP,           // 小跳（跨过小障碍）
  CLIMB_WINDOW,   // 爬上窗口边缘
}

切换规则：
  - 短距离（<200px）：WALK_SLOW
  - 中距离（200-600px）：WALK_FAST
  - 长距离（>600px）：RUN 或 TELEPORT_OUT + TELEPORT_IN
  - 到达目标后 70% IDLE_STAND，30% IDLE_SIT
  - 每次移动 10% 概率触发 PEEK_FROM_EDGE
```

### 1.6 多显示器支持

```
显示器检测：
  - Electron screen.getAllDisplays()
  - 记录每个 display 的 bounds 和 workArea
  - 主显示器 = 用户当前焦点所在显示器

跨屏行为：
  - 虚拟人可在显示器之间移动
  - 跨屏触发条件：
    - 鼠标移动到屏幕边缘 + 虚拟人跟随鼠标
    - 用户工作窗口移动到另一屏幕
    - 随机游荡目标在另一屏幕
  - 跨屏动画：
    - 方案A：直接瞬移（低性能）
    - 方案B：从屏幕边缘走出，延迟 0.5s 后从目标屏幕边缘走入
    - 推荐方案B，增强"她真的在桌面空间里"的幻觉

每个显示器独立配置：
  - scale 可不同（笔记本 0.8，外接显示器 1.2）
  - 是否允许虚拟人进入可配置
  - 任务栏位置不同，边界计算不同
```

  - 显示进度条：人脸解析 → 身体重建 → 拓扑优化 → 材质生成 → 骨骼绑定 → VRM 导出

Step 5: 预览与微调
  - 360° 旋转预览
  - 可调整：肤色、发型、瞳色、服装颜色、身高、体型
  - 可选：AR 试戴（摄像头看虚拟人坐在你肩膀上）

Step 6: 导出与使用
  - 一键导入 WorkOn
  - 可选导出 VRM/GLB（专业版）
  - 生成角色卡（可分享到社区）
```

### 2.3 技术实现方案

#### 2.3.1 单照片流程（基础版）

```
输入：1 张正面人脸照片
输出：头像级 VRM（仅头部 + 简化颈部）

Pipeline:
  1. 人脸关键点检测（MediaPipe / dlib 468点）
  2. 3DMM 人脸重建（FLAME / DECA / EMOCA）
     - 得到中性脸 mesh ~50K tris
     - 得到表情 BlendShape 基
  3. 风格迁移（StyleGAN / diffusion）
     - 将写实 mesh 转为目标风格（二次元/游戏/Q版）
  4. 重拓扑到 ~15K tris
  5. 生成 PBR 贴图：
     - Albedo：从照片 + 生成补全
     - Normal：从深度图生成
     - Roughness/Metalness/AO：默认参数 + 区域推断
  6. 绑定 VRM Humanoid 骨骼（标准 55 骨）

  8. 导出 .vrm 文件

质量：头像可用，身体默认服装
```

#### 2.3.2 多照片流程（标准版/专业版）

```
输入：3-12 张多角度照片
输出：完整半身/全身 VRM

Pipeline:
  1. 多视角人脸重建（MVS + Neural Radiance Fields）
     - 可选方案：InstantAvatar / AvatarMe / GaussianAvatar
  2. 身体重建：
     - 从照片估计 SMPL-X 参数
     - 或直接生成完整 mesh（PIFuHD / PaMIR / ECON）
  3. 服装解析：
     - Segment 服装区域
     - 估计服装 3D 形态（ClothCap / DeepWrinkles）
  4. 头发重建：
     - 从多视角生成 Hair Cards（Neural Haircut）
  5. 风格化（可选）：
     - 输入目标风格 prompt
     - 对 mesh 和贴图做风格迁移
  6. 重拓扑：
     - 标准版：30K tris
     - 专业版：60K tris（游戏级）
  7. 材质生成：
     - Albedo/Normal/Roughness/Metallic/AO/Emission
     - 使用 Stable Diffusion / MaterialGAN 补全未拍摄区域
  8. 骨骼绑定：
     - 标准版：55 骨 VRM humanoid
     - 专业版：80-97 骨（含 SpringBone 头发/服装/配饰）
  9. BlendShape：

  标准版：2-5min
  专业版：10-15min（云端 GPU）
```
