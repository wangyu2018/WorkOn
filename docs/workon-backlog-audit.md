## 一、工作审计（防"脑抽操作"）

### 1.1 什么是"脑抽操作"

指开发/使用过程中因误操作导致的内容丢失或损坏，常见场景：

- 文档写着写着被覆盖/误删，找不到历史版本
- 代码改坏了想回退，但没提交 git
- 某个时段屏幕上出现过的重要信息（客户名、账号、URL、代码片段），事后想不起来
- 误关窗口、误清缓存、误格式化

### 1.2 现有可用的"后悔药"（已实现）

| 能力 | 位置 | 说明 |
|------|------|------|
| Git 历史 | 项目仓库 | 代码/文档的版本回退（`git log` / `git checkout`） |
| OCR 截图落盘 | `userData/screenshots/shot-{ts}.png/jpg` | 桌面截图，保留最近 N 张（默认 200，可配 `ocrCacheLimit`） |
| OCR 结构化快照 | `ocrSnapshots` 表 | 提取的文档名/人名/关键词/URL/代码片段，保留 7 天 |
| 问答（QA） | `qa:ask` / `qa:askStream` | 基于当日分析 + 轨迹 + 习惯的 AI 问答 |
| 日报/周报 | 报表模块 | 当日/本周工作内容汇总 |

### 1.3 审计建议（日常习惯）

1. **重要文档改动前**：先 `git add -A && git commit`，或至少复制一份备份
2. **每天结束**：按 AGENTS.md 推送 git（`daily: yyyy-MM-dd HH:mm`）
3. **发现内容丢失**：优先查 git 历史 → 再查 OCR 截图 → 最后用 AI 问答
4. **定期清理**：`ocrSnapshots` 只留 7 天、截图只留 200 张，重要内容及时导出

## 二、待办：AI 问答恢复指定时段截图（核心需求）

> 目标：当用户"脑抽"丢了内容时，能通过 AI 问答获取**指定时段**的截图/OCR 内容，从而恢复备份。

### 2.1 现状差距（为什么现在做不到）

| 现状 | 问题 |
|------|------|
| 截图文件名只有时间戳，无 OCR 文本关联 | 无法按关键词检索截图 |
| 截图只保留最近 200 张 | 很快被覆盖，历史截图丢失 |
| OCR 原文不落库（`getLastOcrContext` 只留最近一次） | 无法全文检索历史 OCR |
| `qa:ask` 只注入当日分析+轨迹+习惯 | 不含 OCR/截图上下文，AI 答不了"某时段屏幕内容" |

### 2.2 方案设计（建议实现顺序）

#### 阶段 1：建立"截图 ↔ OCR 文本"索引（P0，最优先）

- 在 `ocrWorker.ts` 落盘截图时，把截图路径 + 时间戳 + OCR 文本写入一张新表 `ocrShots`
- 表结构建议：
  ```ts
  interface OcrShot {
    id: string
    ts: number          // 截图时间戳
    file: string        // 截图文件路径（相对 userData）
    text: string        // OCR 原文（可截断，如前 500 字）
    app: string         // 前台应用
    keywords: string[]  // 提取的关键词（复用 classifyOcrText）
  }
  ```
- 保留策略：与 `ocrSnapshots` 一致（7 天），或可配置更长

#### 阶段 2：延长截图保留（P0）

- 当前 `ocrCacheLimit` 默认 200 张，按 OCR 周期（约 30s~1min）很快覆盖
- 建议：截图保留改为**按时间**（如保留 7 天），或提高上限，与 `ocrShots` 索引对齐
- 注意磁盘占用：jpg 压缩（quality 60）约 50KB/张，7 天约 1 万张 ≈ 500MB，需权衡

#### 阶段 3：AI 问答注入 OCR 上下文（P1）

- 新增 IPC：`qa:askWithShots(question, { startTs, endTs })`
- 主进程按时间窗查询 `ocrShots`，把命中文本拼进 system prompt
- 复用现有 `askWithContext` 的流式机制（`qa:askStream`）
- 用户提问示例："今天下午 3 点到 4 点我屏幕上出现过什么客户名？"

#### 阶段 4：渲染端"时间旅行"界面（P2）

- 在 QA 视图或新增视图，提供时间范围选择器 + 关键词搜索
- 展示命中截图缩略图（`file://` 加载 `userData/screenshots/`）
- 支持一键"恢复"：把截图/OCR 文本复制到剪贴板或导出

### 2.3 隐私与安全注意

- 截图含敏感信息（密码、银行、聊天），**必须**沿用现有隐私排除逻辑（`classifyOcrText` 的排除关键词）
- `ocrShots.text` 建议只存提取后的结构化信息，或对原文做脱敏
- 截图文件建议加密或至少限制访问权限
