# WorkOn 界面设计规格 v8 —— 反臃肿 · 千人千态 · AI-Native

> 配套原型：`workon-ainative-prototype.html`（可直接双击打开，四个页签可切换，右上角切深浅色）
> 适用代码：`src/renderer/` · 令牌在 `index.css` · 壳层在 `App.tsx` · 首页在 `HomeView.tsx`

---

## 0. 一句话立场

**现在的 WorkOn 是一套"所有人都看到同一个界面"的效率工具 SaaS。**
它的问题不是配色丑，而是**界面是写死的**：12 个固定导航、十几个永远全量展示的 KPI 卡片、谁打开都是同一张脸。

v8 的方向是把它变成 **AI-native 的个人工作台**：

- **反臃肿** —— 12 个功能入口收敛成 1 个意图入口 + 3 个区域
- **千人千态** —— 首页的**模块、顺序、密度、组件类型**由 AI 按你的行为编排，不是写死的
- **AI-native** —— 结论先行、建议可执行、判断可解释、画像可删除

## 1. 诊断：现在为什么难看、为什么臃肿

### 1.1 视觉层（截图里能直接看到的）

| # | 问题 | 具体表现 | 根因 |
|---|---|---|---|
| 1 | **冷暖双色系打架** | 画布暖米 `#F7F4EE`，卡片青瓷绿 `#E9F1EC` | `ink` 主题同时定义了两套色相做表面 |
| 2 | **卡片和子卡片同色** | `--bg-surface` 和 `--surface-2` 都是绿系，嵌套无层次 | 层次靠"换底色"而非阴影 |
| 3 | **零投影** | 浅色模式卡片没有阴影，糊成一片 | 只定义了 `shadow-sm/md/lg` 三档且未系统使用 |
| 4 | **侧栏和内容区同底色** | 分不清"外壳"和"画布" | `--chrome` 未独立 |
| 5 | **emoji 当图标** | 导航 🏠📅🎯、视角 🎨🛠📈、窗口按钮 `– ▢ ✕` | 没有图标系统 |
| 6 | **橙色一词二义** | 同时表示「已逾期」和「导航选中」 | 语义色未隔离 |
| 7 | **字号全是 13px** | 层次全靠颜色 | 没有字阶 |
| 8 | **注意力环 40 孤零零** | 占半屏却只有一个数字 | 单指标做成主视觉 |

### 1.2 结构层（更严重）

| # | 问题 | 数据 |
|---|---|---|
| 9 | **导航臃肿** | 12 个入口：首页/日历/计划/主线/报表/知识库/桌搭/问答/画像/隐私/设置/监控 |

| 14 | **画像藏在二级页** | "它记得我什么"是 AI-native 的信任基础，却被藏起来 |

## 2. 信息架构：12 页 → 3 区 + 1 入口

### 2.1 目标结构

```
┌────┬──────────────────────────────────────────────┐
│    │  意图输入条：「你想做什么…」        ⌘K  ⏎    │  ← 唯一主角
│ 现 ├──────────────────────────────────────────────┤
│ 在 │  ① AI 判断（结论 + 依据 + 可执行动作）          │  ← 千人千态编排的第一块
│    │  ② …按人编排的模块 2..N                       │
│    │  ③ 为什么是这 5 块 ▾（可解释 + 可编排）        │
│回看│                                  ┌───────────┐│
│    │                                  │ 姵儿的判断 ││
│陪伴│                                  ├───────────┤│
│    │                                  │ 隐私与记忆 ││  ← 固定，不藏
│    │                                  ├───────────┤│
│    │                                  │ 它在学你   ││  ← 可解释的个性化
│ ⚙  │                                  └───────────┘│
└────┴──────────────────────────────────────────────┘
                              悬浮件：一句建议 + 两个动作
```

### 2.2 导航收敛

| 区域 | 收纳了什么 | 入口方式 |
|---|---|---|
| **现在** | 首页、时间轴、计划（今日）、监控、待办、确认队列 | 默认页 + 意图直达 |
| **回看** | 报表、日报、热度图、画像、问答、知识库、隐私 | 单一入口，日/周/月三档 + 提问 |
| **陪伴** | 桌搭、对话、气泡、主动提醒、人格 | 单一入口 + 桌面悬浮件 |
| **系统** | 设置、主题、快捷键、数据管理 | 侧栏底部齿轮 |

**12 → 4**。其余 9 个页面的内容不消失，而是变成**意图的解析结果**：
用户说「昨天摸鱼多久」，直接落到回看的时间轴，不经过任何导航。

### 2.3 侧栏

- 76px 细栏，图标 + 9px 文字，选中态 2px 左侧竖条 + 强调色底
- 底部：**用户头像**（点开是"换个人看看"/设置），不是孤零零一个设置齿轮
- 移除"视角"三选一（晨/昼/晚）——它被吸收进千人千态编排，变成隐性参数

## 3. 千人千态：版面编排引擎（四层）

这是 v8 的核心。首页不是写死的，而是**四层机制算出来的**。

```
第 1 层  资格    这个模块今天有没有出现的资格？（有数据？当前时段相关？）
   ↓
第 2 层  评分    有资格之后，打多少分？（时段能量 × 当前链路 × 历史使用频次 × 风险）
   ↓
第 3 层  排序    按分排序，取前 N（3–5 块），同分按固定优先级
   ↓
第 4 层  覆盖    用户显式偏好（锁位置 / 隐藏 / 手动排序）优先级最高
```

### 3.1 模块注册表

每个模块声明三件事，编排器只看这三个字段：

```ts
interface BoardModule {
  id: string
  /** 资格：没有数据就不出现，避免"今天的摸鱼时间 —"这种噪音 */
  eligible(ctx: TodayCtx): boolean
  /** 评分：0–100，越高越靠前 */
  score(ctx: TodayCtx): number
  /** 兜底优先级：同分时用 */
  base?: number
}
```

### 3.2 评分因子

| 因子 | 权重 | 说明 |
|---|---|---|
| 时段能量 | 0.25 | 用户自己的高专注时段（如上午 10–12 点） |
| 当前链路 | 0.25 | 正在做的事必须可见（断点 > 进度） |
| 历史频次 | 0.20 | 这人过去 7 天实际打开过哪个模块 |
| 风险信号 | 0.20 | 逾期、久未推进、识别推翻 |
| 新鲜度衰减 | −0.10 | 连续 3 天出现则降权，避免"每天同样的首页" |

### 3.3 三种典型人（原型里可直接切）

| | 深潜型 | 冲刺型 | 记录型 |
|---|---|---|---|
| 特征 | 长链路 · 低切换 | 多项目 · 高切换 | 复盘 · 画像 · 节律 |
| 版面 | 判断 / 深度块 / 链路 / 打断保护 / 待确认 | 判断 / 四线泳道 / 风险 / 排期 / 时间轴 | 判断 / 节律热力 / 日记 / 周对比 / 链路画像 |
| 模块数 | 5 | 5 | 5 |
| 组件类型 | 会话卡 + 进度链 | 泳道表 + 风险列表 | 热力图 + 雷达 + 日记 |
| 密度 | 紧凑 | 宽松 | 宽松 |
| 语气 | 少废话，只给动作 | 先给全景再给建议 | 先给观察再给结论 |

**同样 5 个模块，但模块不同、顺序不同、组件形态不同、密度不同。** 这就是千人千态的可验证形态。

### 3.4 可解释 + 可覆盖（缺一不可）

- 首页底部固定一块 **「为什么今天是这 N 块」**，逐条列出：模块名 + 入场理由 + 触发因子（按时段 / 按状态 / 按频次 / 固定）
- 点「编排」进入拖拽排序与隐藏
- 用户每次点「这个建议没用」，该模块权重 −1，第二天起不再主动出现

## 4. AI-Native 的 8 条界面准则

| # | 准则 | 落地要求 |
|---|---|---|
| 1 | **意图优先** | 一个输入取代 12 个导航；⌘K 常驻；输入框 placeholder 随人变化 |
| 2 | **结论先行** | 先给判断和动作，数字是论据；禁止"先给 20 个指标再让你自己总结" |
| 3 | **建议可执行** | 每条建议必须带一键落地（排进今天 / 开深度块 / 立待办 / 写入知识库） |
| 4 | **可解释** | 每条 AI 判断可展开依据（≥3 条量化依据），并显示置信度 |
| 5 | **连续上下文** | 页面是同一段对话的投影；任意卡片可"继续问" |
| 6 | **主动而克制** | 主动提醒有**每日预算**（默认 4 次），且只在你历史上接受过的类型开口 |
| 7 | **可遗忘** | 「它记得你什么」「它在学你」是首页固定模块，可逐条关闭、可删除画像 |
| 8 | **可校准** | 摸鱼阈值、提醒时机、深度块长度随你的反馈漂移，而不是写死 |

> 第 7 条是硬性要求：**这条不做，个性化就只是打扰。** 隐私页要从二级页提到首页常驻。

## 5. 设计令牌 v8

替换 `index.css` 的 `:root` 令牌段。**核心原则：单一色相族做表面，颜色只表达语义。**

### 5.1 表面（解决冷暖打架）

浅色用**暖纸画布 + 中性白卡**（保留他们喜欢的暖，但卡片不再染绿）：

```css
[data-mode="light"]{
  --canvas:#F3F1ED;   /* 暖纸画布 */
  --s1-bg:#FFFFFF;    /* 卡片：中性白，不带色相 */
  --s2-bg:#FAF9F7;    /* 卡内嵌套 */
  --s3-bg:#F1EFEB;    /* hover / active */
  --inset:#F5F4F1;    /* 输入井 / 进度轨道 */
  --chrome:#EFEDE8;   /* 侧栏 / 顶栏，独立于画布 */
  --line:#E6E2DA;     /* 发丝边 */
  --line-2:#D7D2C8;
  --line-3:#C4BEB2;
}
```

深色用**静谧深空**（非纯黑，纯黑会让层次消失）：

```css
[data-mode="dark"]{
  --canvas:#0D0E11;
  --s1-bg:#15171B;
  --s2-bg:#1B1E23;
  --s3-bg:#23262C;
  --inset:#101216;
  --chrome:#111318;
  --line:rgba(255,255,255,.075);
  --line-2:rgba(255,255,255,.13);
  --line-3:rgba(255,255,255,.20);
}
```

### 5.2 文字 4 阶

```css
[data-mode="light"]{ --tx1:#17161A; --tx2:#54514A; --tx3:#8A867C; --tx4:#ADA79A; }
[data-mode="dark"] { --tx1:#ECEDEF; --tx2:#A3A7AF; --tx3:#70747E; --tx4:#4B4F58; }
```

### 5.3 语义色（解决一词二义）

**核心约束：一个颜色只做一件事，任何两个语义不得共用。**

| 令牌 | 浅色 | 深色 | 唯一职责 |
|---|---|---|---|
| `--accent` | `#0E8C7F` | `#14B8A6` | 选中态、主按钮、进度、焦点 |
| `--ok` | `#15803D` | `#22C55E` | 已完成 |
| `--warn` | `#B45309` | `#F59E0B` | 逾期、临期、风险 |
| `--danger` | `#DC2626` | `#EF4444` | 破坏性操作、错误 |
| `--slack` | `#C2703C` | `#E08A4C` | 摸鱼（**不再用红色**） |
| `--focus` | `#2F7DD1` | `#5B9BF0` | 工作时长 |
| `--aura` | `#6366F1→#8B5CF6→#06B6D4` | 同 | **仅 AI 语义面**，禁止外溢做装饰 |

> 注意：`#0FB5A4` 在白底上做 12px 小字对比度不足（约 2.3:1），浅色模式的强调色必须压深到 `#0E8C7F`（约 4.0:1）。这是他们现在浅色模式"发飘、看不清"的原因之一。

### 5.4 圆角 / 阴影 / 间距 / 字阶

```css
--r-xs:6px; --r-sm:8px; --r-md:12px; --r-lg:16px; --r-xl:20px; --r-full:999px;
/* 替换现有的 10/14/18/22 —— 6 档足够，4 个非标值只会导致随手乱用 */

--s1:4px; --s2:8px; --s3:12px; --s4:16px; --s5:20px; --s6:24px; --s8:32px;

--t-display:28px/34px 600;  --t-h1:21px/28px 600;
--t-h2:16px/23px 600;       --t-h3:14px/20px 500;
--t-body:13px/20px;         --t-sm:12px/18px;
--t-cap:11px/16px;          --t-micro:10px/14px + .12em 字距（分组标签）
```

**5 级阴影**（浅色靠阴影，深色靠发丝边）：

```css
[data-mode="light"]{
  --e1:0 1px 2px rgba(28,24,18,.05);
  --e2:0 1px 2px rgba(28,24,18,.05), 0 4px 12px -3px rgba(28,24,18,.07);
  --e3:0 2px 4px rgba(28,24,18,.05), 0 12px 28px -8px rgba(28,24,18,.12);
  --e4:0 8px 20px rgba(28,24,18,.10), 0 28px 64px -14px rgba(28,24,18,.20);
  --ring:0 0 0 3px rgba(14,140,127,.16);
}
```

### 5.5 动效 4 档

```css
--e-out:cubic-bezier(.22,1,.36,1);
--e-spring:cubic-bezier(.34,1.32,.64,1);
--t-micro:120ms; --t-hover:160ms; --t-panel:240ms; --t-page:320ms; --t-ring:640ms;
```

保留他们现有的 `data-anim=off` 开关，并补 `prefers-reduced-motion`。

### 5.6 图标

**全部换成内联 SVG**：24 网格 / 1.8 描边 / 圆头圆角。
需要替换的地方：`App.tsx` 的导航、视角切换、窗口按钮；各 View 的 `CategoryIcon.tsx`。
`Icon.tsx` 已有骨架，扩充即可，不要引入 emoji。

## 6. 组件规范

每个组件必须有 **5 态**：默认 / hover / active / focus-visible / disabled。

| 组件 | 规范 |
|---|---|
| **按钮** | 主要（accent 实心 + 阴影）、次要（白底 + 发丝边）、幽灵（无底）、AI（aura 渐变，仅 AI 动作）、危险（danger 描边）。`:active` 统一 `scale(.975)` |
| **卡片** | `--r-lg` + `--line` + `--e1`；hover 升 `--e3` + `translateY(-2px)`；**不要**用不同底色表达嵌套 |
| **徽标** | `h20 / radius-full / 11px`；wash 底 + 实色字。语义严格按 §5.3 |
| **输入** | `--inset` 井底 + 发丝边；focus = accent 边 + 3px `--ring` |
| **进度** | 轨道 6px `--inset`，填充跟随语义色（逾期用 danger，落后用 warn） |
| **AI 判断卡** | aura 顶部渐变条 + 结论（15px/24）+ 依据折叠区 + 一键动作行 + 置信度 |
| **空状态** | **空即行动**：一句说明 + 一个按钮，禁止留白 |
| **骨架屏** | `--s3-bg` 底 + 微光扫过，禁止 spinner |
| **错误** | `ERR_XXX｜来源｜重试` 三段式 + 「立即重试」按钮（沿用 BACKLOG ⑤） |

## 8. 验证方式

打开原型，**只需要看一件事**：切换左上角「深潜型 / 冲刺型 / 记录型」，
首页的**模块、顺序、组件形态、密度**会全部改变 —— 而数据是同一天的。

这就是"千人千态"唯一需要被证明的事。
