# WorkOn 产品流程重构规格 v2.3 — 启动仪式 × 导航重组 × 全局交互 × 性能感知

> 基于 v2.0-2.2 设计规格，重新设计整个产品的使用流程和导航架构
> 核心变革：从8图标平铺 → 精简5核心模块 + 2全局能力 + 1隐藏设置
> 产品不再是"8个页面"，而是"一个虚拟助理 + 5个工作场景"

---

## 一、导航架构重组

### 1.1 当前问题

| 问题 | 现状 | 用户感受 |
|------|------|---------|
| 导航太杂 | 8个灰图标平铺一行 | "有点杂乱"，不知道先看哪个 |
| 功能重叠 | 热度图和日历都是时间线 | 两个页面看差不多的东西 |
| Q&A独立太浪费 | 单独一个问答页 | 问答应该是全局随时用的 |
| 画像独立太深 | AI画像只在AIView | 分析应该融入日报 |
| 无启动仪式 | 直接进入空白界面 | 冷启动体验差 |
| 桌宠只是装饰 | 单独页面看表情 | 应该是实时助理而非静态展示 |

### 1.2 新导航架构

```

## 二、启动仪式（Boot Ritual）

### 2.1 每日启动流程设计

```
设计WorkOn每日启动仪式——从冷启动到进入工作状态的完整体验。

启动阶段拆解（4个阶段，总耗时8-15秒）：

=== PHASE 1: 系统唤醒（0-3秒） ===

全屏暗场，中心出现虚拟人"休眠态"（半透明0.6，闭眼，微弱呼吸动画）

动画序列：
  0.0s — 屏幕全黑，只有极微弱的背景网格线（#0a0d14底色上rgba(124,158,255,0.02)网格）
  0.5s — 中心虚拟人轮廓从0透明度→0.6透明度淡入（0.5s ease-out）
  1.0s — 虚拟人呼吸动画开始（3.6s周期胸部起伏）
  1.5s — 微弱环境光点开始出现（随机位置，0.3透明度，缓慢飘动）
  2.0s — 底部出现一行微光文字："WorkOn 系统唤醒中..."（caption size，accent-blue色）
  2.5s — 背景网格线亮度从0.02→0.05渐变（系统"通电"视觉）
  3.0s — 网格线脉冲一次（0.05→0.1→0.05，0.3s），模拟"信号确认"

性能感知决策（在Phase 1后台执行）：
  系统检测：
    - CPU占用率（当前+5分钟均值）
    - 内存可用量（GB）
    - GPU是否可用（WebGL check）
    - 显示器数量（单屏/双屏）
    - 上次启动时间（判断是否当日首次启动）
  
  决策矩阵：
    ┌──────────────┬──────────────────┬──────────────────┐
    │ 资源等级     │ 动画质量         │ 虚拟人渲染       │
    ├──────────────┼──────────────────┼──────────────────┤
    │ 高(CPU<30%   │ 全部动画+特效    │ 15000面+cel-shade│
    │ RAM>4GB可用) │ 粒子系统+光效    │ 4级描边+SSS      │
    ├──────────────┼──────────────────┤──────────────────┤
    │ 中(CPU<60%   │ 核心动画+简化特效│ 8000面+3级着色   │
    │ RAM>2GB可用) │ 减少粒子密度     │ 2级描边          │
    ├──────────────┼──────────────────┤──────────────────┤
    │ 低(CPU>60%   │ 仅关键过渡动画   │ 3000面+2级着色   │
    │ RAM<2GB可用) │ 无粒子系统       │ 无描边+基础纹理  │
    └──────────────┴──────────────────┴──────────────────┘
  
  决策结果存储到全局状态：animationLevel = 'full' | 'medium' | 'minimal'
  后续所有动画和虚拟人渲染都基于此级别降级

=== PHASE 2: 虚拟人觉醒（3-6秒） ===

虚拟人从休眠态→觉醒态的动画序列：

  3.0s — 虚拟人透明度0.6→1.0（0.5s淡入）
  3.5s — 虚拟人眼睛从闭合弧线→半开（0.3s，"刚醒来"表情）
  4.0s — 虚拟人眼睛完全睁开→看向用户方向（0.3s）
  4.5s — 虚拟人嘴角从平线→微微笑（0.2s，"早安"表情）
  5.0s — 虚拟人做一个小伸展动作（手臂微抬+肩部放松，0.5s）
  5.5s — 根据性格角色发出问候语（文字气泡浮出）：

    ARIA: "系统就绪。专注度昨日均值82%，今日建议保持上午高效时段。"
    LUNA: "早安~ 今天又是元气满满的一天哦！(≧▽≦)"
    KIRA: "醒了？别想摸鱼，我在看着你。(╬▔皿▔)←"
    ZEN: "嗯...新的一天，顺其自然吧~"
    SHIN: "07月21日。昨日达成率84%。今日目标：90%。开始工作。"

  同时：背景从纯暗场→渐变出现微弱的深空星点效果
  光照从"夜间模式"→"工作日晨光"过渡（色温从暖橙→冷蓝白渐变，1s）

=== PHASE 3: 初始化问答（6-12秒，可跳过） ===

虚拟人觉醒后，自动发起"晨间规划问答"。

对话框设计：虚拟人旁边浮出glass-card对话面板（280×200px）

问题1（必问）："今天有什么计划？"
  输入方式：自然语言textarea（3行高度）
  用户输入示例："上午写PRD文档2小时，下午调试数据质量3小时，3点有个团队会议"
  AI实时解析显示（输入过程中，下方逐步出现解析预览）：
    "检测到 3 项计划：
     ✎ 完成PRD文档 | 预计2h | 写作状态 | 建议09:00-11:00
     ✎ 调试数据质量 | 预计3h | 编码状态 | 建议13:00-16:00
     ✎ 团队会议 | 预计1h | 会议状态 | 建议15:00-16:00
    [全部采纳] [逐条调整] [跳过]"

  快速选项（如果不想输入）：
    [沿用昨日计划] [从Oner同步] [空白开始] [AI推荐计划]

  如果选择"沿用昨日计划"：
    虚拟人："昨日的计划达成率84%，未完成项：调试数据质量。是否延续？"
    显示昨日计划列表 + checkbox选择延续哪些

  如果选择"从Oner同步"：
    虚拟人："检测到Oner待办3项..." 显示列表 + 采纳

问题2（可选，基于昨日数据智能提问）：
  如果昨日摸鱼超过30分钟：
    "昨日摸鱼45分钟集中在14:00-14:45，今天要不要设置专注提醒？"
    [设置提醒] [不需要] [那个时段安排低优先级任务]
  
  如果昨日加班：
    "昨日加班到19:30，今天确保按时下班？"
    [设定18:00截止] [正常安排] [今天可能还要加班]
  
  如果连续3天达成率<70%：
    "连续3天达成率偏低，建议今天精简计划聚焦核心任务。"
    [采纳建议] [正常安排]

问题3（可选，心情/角色切换）：
  "今天想用哪个角色？"
  [ARIA冷静] [LUNA温暖] [KIRA毒舌] [ZEN佛系] [SHIN严厉]
  或：[沿用默认] 
  如果切换角色：虚拟人外观+性格瞬间切换（0.3s morph动画）

SKIP选项：
  右上角[跳过启动仪式]按钮 → 快速进入工作界面
  设置中可配置：每次启动/仅首次启动/关闭仪式

=== PHASE 4: 进入工作状态（12-15秒） ===

两种进入方式（根据启动设置选择）：

方式A："科幻进入"（默认）
  12.0s — 对话面板收起（0.3s fade-out）
  12.3s — 虚拟人站在屏幕中央
  12.5s — 背景开始"数据流"动画：
    从中心向外扩散的数据粒子环（accent-blue色）
    环扩散到屏幕边缘（1.0s），形成"系统界面展开"视觉效果
  13.5s — 数据环到达边缘时，界面从边缘向中心"生长"：
    导航栏从左侧淡入（0.3s stagger）
    日历视图从中心展开（0.5s scale from 0.8→1.0）
    状态条从顶部滑入（0.2s translateY）
  14.0s — 虚拟人开始"定位移动"动画：
    从屏幕中心→右下角预设位置（1.0s）
    移动路径：直线+轻微弧度（不是机械直线）
    移动时身体微前倾（走路姿态），头发轻微向后飘
    到达位置后：0.2s bounce-settle（轻微弹跳稳定）
  14.5s — 到达预设位置后，虚拟人恢复当前状态表情
  15.0s — 完全进入工作界面，虚拟人在右下角开始日常循环

方式B："直接进入"（快速模式）
  12.0s — 对话面板收起
  12.2s — 界面瞬间出现（0.3s总过渡，不做科幻动画）
  12.5s — 虚拟人直接出现在预设位置（0.2s淡入，不做移动动画）
  12.7s — 进入工作状态

预设位置记忆：
  虚拟人记住用户上次放置的位置（localStorage）
  如果是首次启动：默认右下角（距离右边缘40px，距离底边缘40px）
  用户可拖拽到任何位置，下次启动自动定位到该位置

进入后的初始视图：
  默认显示"日历"视图（直观看到今天的时间安排）
  如果启动时输入了计划：日历视图上自动标注计划块
  如果启动时跳过了：显示空白日历+虚拟人提示"还没有今天的计划哦"
```

### 2.3 非首次启动（当日第二次打开）

```
当日第二次启动WorkOn的体验设计（快速唤醒，不重复仪式）。

检测条件：localStorage中记录了当日首次启动时间，
  且当前时间在同一天内 → 判定为"当日复启"

复启流程（3-5秒）：
  0.0s — 暗场0.3s

## 三、虚拟人实时工作反馈系统

### 3.1 状态头顶指示器

```
设计虚拟人头顶的状态指示器系统——实时反馈工作状态。

指示器类型（根据当前状态自动切换）：

① 番茄倒计时环（专注/编码/写作/AI开发等高效状态）
   - 位置：虚拟人头顶正上方20px
   - 外观：mini ProgressRing 24px + 剩余时间文字
   - 数据：基于番茄工作法设定（默认25分钟周期）
   - 显示："12:35" 剩余分钟+秒
   - 环颜色：accent-green（专注态）→ 随状态变accent色
   - 当倒计时<5分钟：环变黄色，文字微微放大（紧迫感）
   - 当倒计时=0：环消失，虚拟人做"完成"表情（0.3s），
     弹出微提醒："番茄钟完成！休息5分钟？"
     [休息5分钟] [继续下一个] [跳过]
   - 用户可自定义番茄时长：设置中配置15/25/30/45/60分钟

② 摸鱼计时器（摸鱼/放松等低效状态）
   - 位置：虚拟人头顶正上方20px
   - 外观：红色数字计时器（不是环，是数字）
   - 显示："摸鱼 15:42" 纯数字，accent-red色
   - 当摸鱼>15分钟：数字开始脉冲闪烁（1.5s周期）
   - 当摸鱼>30分钟：数字变大+虚拟人表情变愤怒
   - 当摸鱼>60分钟：数字占满头顶区域+虚拟人叉腰
   - 设计意图：让摸鱼时间可视化，制造"被计时"的紧迫感

③ 会议剩余时间（会议状态）
   - 位置：虚拟人头顶正上方20px
   - 外观：mini ProgressRing 24px + "会议剩余"文字
   - 数据：基于CalendarView中的会议PlanItem时长
   - 显示："会议 32:15" 剩余分钟
   - 环颜色：accent-warm（暖橙）
   - 当会议即将结束(<5分钟)：环变黄色+虚拟人做"快结束了"微表情

④ 任务进度条（AI开发/调试等长任务状态）
   - 位置：虚拟人头顶正上方20px
   - 外观：mini水平进度条（40×6px）+ 百分比文字
   - 数据：基于PlanItem的matchScore或自定义进度
   - 显示："编码 67%" 进度条+数字
   - 进度条颜色：accent-blue→accent-green渐变填充
   - 到100%：进度条闪烁0.3s+虚拟人庆祝表情

## 七、性能感知渲染系统

```
设计WorkOn性能感知渲染系统——根据系统资源自动降级。

检测频率：
  启动时检测1次（决定初始级别）
  运行中每60秒检测1次（动态调整）
  用户手动触发（设置中的"资源诊断"按钮）

检测指标：
  cpuUsage: 当前CPU占用百分比
  memoryAvailable: 可用内存GB
  gpuAvailable: WebGL是否可用
  gpuPerformance: GPU渲染速度（simple benchmark）
  monitorCount: 显示器数量
  fps: 虚拟人当前渲染帧率

级别切换规则：
  full → medium: CPU>50%持续5分钟 OR 内存<3GB OR fps<25
  medium → minimal: CPU>70%持续5分钟 OR 内存<1.5GB OR fps<15
  minimal → medium: CPU<40%持续5分钟 AND 内存>3GB
  medium → full: CPU<25%持续5分钟 AND 内存>5GB AND fps>28

级别切换动画：
  0.3s过渡——不突然切换，平滑降级
  降级时：虚拟人微缩+粒子减少+动画减慢
  升级时：虚拟人微扩+粒子恢复+动画加速
  用户通知：toast提示"系统资源紧张，动画已降级" / "资源恢复，动画已升级"
  用户可手动选择级别（覆盖自动决策）

各级别渲染规格：

  FULL（高资源）：
    虚拟人：15000面+4级cel-shade+SSS+变化宽度描边+6层眼睛+多层头发
    动画：30fps循环+物理头发+衣物微动+全部表情动画
    粒子：满密度+光效+阴影
    遮挡：六角网格屏障+光效动画+能量脉冲
    UI：所有glass-card+blur+glow+全微交互
    启动仪式：科幻进入全动画

  MEDIUM（中资源）：
    虚拟人：8000面+3级着色+2级描边+简化眼睛+基础头发
    动画：24fps循环+简化头发+2级表情变化
    粒子：减半密度+简化光效
    遮挡：渐变雾罩（不渲染六角网格）
    UI：glass-card但减少blur+简化glow+保留核心微交互
    启动仪式：简化进入（去掉数据粒子环）

  MINIMAL（低资源）：
    虻拟人：3000面+2级着色+无描边+基础纹理+简化眼睛
    动画：15fps循环+无头发物理+3级表情(开心/中性/不开心)
    粒子：无粒子系统
    遮挡：角色走挡（纯角色移动+半透明overlay，不渲染特效）
    UI：基本card+无blur+无glow+仅关键过渡动画
    启动仪式：直接进入（0.3s总过渡）

  CRITICAL（极端低资源，CPU>85%）：
    虚拟人：静态PNG sprite（3帧表情切换）+无3D渲染
    动画：无连续动画，仅状态切换0.2s过渡
    粒子：无
    遮挡：纯半透明overlay（0.7透明度灰色遮罩）
    UI：纯平面+无动画+最小CSS
    启动：瞬间进入
    自动弹出："系统资源极度紧张，WorkOn已切换到极简模式"
    [保持极简] [关闭WorkOn释放资源]

## 八、虚拟人→Oner双向数据流

```
设计WorkOn与Oner的双向数据同步协议。

同步架构：

┌──────────────┐          ┌──────────────┐
│   WorkOn     │◄────────►│    Oner      │
│  (时间监控)   │  双向同步  │  (任务管理)   │
└──────────────┘          └──────────────┘

同步协议（基于Oner支持的接口方式）：

方式1：本地文件同步（如果Oner支持本地数据文件）
  WorkOn读取Oner数据目录 → 解析待办 → 导入PlanItem
  WorkOn写入Oner数据目录 → 更新任务状态 → 推送小结

方式2：API同步（如果Oner提供REST/WebSocket API）
  WorkOn调用Oner API → GET待办列表 → 导入PlanItem
  WorkOn调用Oner API → PATCH任务状态 → 推送小结

方式3：插件桥接（如果Oner支持插件系统）
  WorkOn插件 → 在Oner内部运行 → 直接读写Oner数据
  优点：最紧密集成，实时同步

同步内容详细定义：

WorkOn → Oner（推送方向）：

① 任务完成推送：
  触发：PlanItem.status变为'done'
  数据：
    extId: oner任务ID
    status: 'done'
    actualDuration: 实际耗时分钟
    focusScore: 该时段专注度均值
    workState: 实际工作态
    notes: WorkOn备注
  格式：JSON

② 任务取消推送：
  触发：PlanItem.status变为'cancelled'
  数据：
    extId: oner任务ID
    status: 'cancelled'
    reason: 取消原因（用户选择或AI推断）

③ 每日小结推送：
  触发：每日复盘完成时 / 手动触发
  数据：
    date: YYYY-MM-DD
    totalWorkMin: 总工作时长
    totalSlackMin: 总摸鱼时长
    focusScoreAvg: 平均专注度
    achievementRate: 达成率
    completedTasks: [完成项列表]
    cancelledTasks: [取消项列表]
    unfinishedTasks: [未完成项列表+预计明日完成时间]
    aiInsight: AI洞察摘要（1-2句）
  格式：JSON → Oner备忘插件渲染为可读文本

④ 状态实时推送（可选，高频）：
  触发：WorkState变更时
  数据：
    currentState: 当前工作态
    currentApp: 当前应用
    duration: 已持续时间
  用途：Oner可以显示"用户当前正在编码(已2h)"状态标签

Oner → WorkOn（拉取方向）：

① 待办同步：
  触发：启动仪式"从Oner同步" / 手动触发 / 定时(每30分钟)
  数据：
    tasks: [待办任务列表]
    每项：{id, title, tags, estimatedDuration?, priority?, dueDate?}
  处理：每个任务→生成PlanItem(source='oner', extId=oner.id)

② 任务更新同步：
  触发：Oner中任务被修改/完成/取消
  数据：{id, status, title?, duration?}
  处理：更新对应PlanItem

③ 标签映射：
  Oner标签 → WorkOn类别映射规则（可配置）：
    oner标签"编码/开发/code" → category='aidev'
    oner标签"文档/writing/写" → category='writing'
    oner标签"会议/meeting/会" → category='meeting'
    oner标签"客户/client/客" → category='client'
    oner标签"个人/personal/个" → category='personal'
    未匹配 → category='other'

同步冲突处理：
  如果WorkOn和Oner同时修改了同一任务：
  以"最后修改时间"为准
  如果时间差<5分钟：提示用户选择
  "Oner中该任务被标记为进行中，WorkOn中被标记为已完成。选择："
  [采纳WorkOn(已完成)] [采纳Oner(进行中)] [手动解决]

同步状态指示：
  规划视图顶栏：
  "Oner同步：●已连接 · 3项待办待导入 · 2项完成待推送"
  每个PlanItem右侧：[↗已推送] / [⏳待推送] / [✗推送失败]
```
