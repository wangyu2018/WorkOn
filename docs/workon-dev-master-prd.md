## 一、产品概述

**WorkOn** 是一款桌面效率监控工具，核心创新是**动漫虚拟人 + 监控数据驱动 + 情感交互闭环**。

不是传统的番茄钟/时间追踪/专注软件——而是一个**住在桌面上的虚拟伙伴**，通过屏幕分析+窗口检测+输入检测实时感知你的工作状态，用3D虚拟人同步反映状态，并在摸鱼时渐进式干预、在加班时智能确认、在疲劳时关怀提醒。

### 核心价值

1. **虚拟人实时反映** — 你编码时角色贴屏狂敲键盘，摸鱼时角色抱手机瘫坐，会议时端正微笑
2. **监控驱动交互** — 不是定时提醒，而是基于实际数据的智能决策（下班预测/进度预警/摸鱼干预）
3. **情感伙伴关系** — 5种性格角色，PAD情感引擎，5级关系进化，越用越懂你
4. **渐进式干预** — 温和提醒→走过来说话→遮挡屏幕→强制锁定，4级递进不暴力

## 五、技术栈建议

### 前端

| 层面 | 技术 | 理由 |

| 层面 | 技术 | 理由 |
|------|------|------|
| 桌面框架 | Electron | 透明窗口+跨平台 |
| 数据存储 | SQLite (better-sqlite3) | 本地结构化数据 |
| 屏幕分析 | 本地AI模型 / 在线API | 可配置 |
| 窗口检测 | active-win /Electron API | 获取活跃窗口 |
| TTS | Edge TTS (edge-tts) | 默认引擎 |
| 宠物检测 | Qwen3-VL 8B + vLLM | 本地推理 |

## 六、给 Coding 编辑器的使用指南

### 6.1 开发顺序

**严格按照 Phase 0 → 1 → 2 → 3 → 4 的顺序开发**，不要跳过。

每个 Phase 的任务可以并行，但 Phase 之间有依赖：
- Phase 0 是所有后续的基础（Three.js跑不通，后面都白搭）
- Phase 1 的监控引擎是 Phase 2 智能闭环的数据源
- Phase 2 的交互系统是 Phase 3 情感表达的载体
- Phase 3 的UI框架是 Phase 4 高级能力的容器

### 6.2 查阅规则

1. **开发某个功能时**，先查本文档第四节找到对应Phase和任务
2. **看规格引用列**，找到对应的v2.x文档
3. **去v2.x文档的对应章节**，那里有完整的中英文提示词/数据结构/动画规格
4. **注意交叉引用**——一个功能可能跨多个文档（如番茄钟联动需要v2.5第一章+v2.4情感系统）

### 6.3 提示词使用

v2.0中的30种状态3D渲染提示词、v2.4中的7种情感渲染提示词，是**给3D建模/AI图像生成的素材**，不是前端代码。使用方式：

1. 用提示词生成3D模型参考图/VRM模型
2. 或用提示词指导Three.js着色器和动画参数
3. 数据结构（TypeScript interface）和CSS是直接可用的代码

### 6.4 务必注意的设计原则

1. **虚拟人不是装饰** — 每个动画/表情/行为都必须由数据驱动，不是随机播放
2. **渐进式干预** — 永远从P1气泡开始，不要一上来就遮挡屏幕
3. **情景感知** — 深度专注时必须静默（P0），这是不可违反的原则
4. **5性格差异** — 同一行为5种角色必须有不同表现（动画强度/话语/粒子量）
5. **性能优先** — 虚拟人不能影响用户工作，CPU>8%就降级
6. **即时预览** — 设置面板所有修改即时生效，不要"保存后生效"

### 6.5 数据驱动核心公式

```
监控数据 → WorkState → 情景评估 → 通知决策 → 交互行为 → 虚拟人动画
    ↑                                                      ↓
    └──────────── 用户反馈 → 学习引擎 ←────────────────────┘
```

所有交互都是这个闭环的一部分。不要做"没有数据支撑的动画"。
