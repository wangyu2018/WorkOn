# 特定角色 · 特定场景测试用例文档 v2（165 例）

> 目标：把「情报 / 工作流 / 问答 / 知识 / 回顾」五条内部闭环，以及「外部 Agent 输入输出」这条跨 Agent 链路放回真实角色的一天里验证，而不是只验证按钮存在。
> 数据口径：测试数据统一使用 `SCENARIO-` 前缀或 `source=intel|knowledge|workflow|qa`；每轮结束必须清理，不伪造工作流运行数据。
> 关联台账：`REQ-20261120-01`（P0 归档）、`REQ-20261120-02`（P1 闭环）
> 演示材料：`docs/art/p1-demo/DEMO-REPORT.html`

## 1. 闭环范围

| 编号 | 闭环 | 入口 | 落点 |
| --- | --- | --- | --- |
| C1 | 情报 → 计划 | 情报流「转今日计划」 | 计划页今日 |
| C2 | 工作流产物 → 知识 | 作战板「存入知识」 | 回顾 · 知识沉淀 |
| C3 | 问答 → 知识 | 回答底部「存入知识」 | 回顾 · 知识沉淀 |
| C4 | 知识 → 计划 | 知识详情「转为今日计划」 | 计划页今日 + 知识 `links` |
| C5 | 回顾 → 顺延 | 今日 / 本周回顾「顺延」 | 次日 / 下周一计划 |

## 2. 测试角色

| 角色 | 画像 | 核心诉求 | 重点 |
| --- | --- | --- | --- |
| R1 林一 · 多项目产品经理 | 5 个项目并行；每天 3–5 条情报；会议打断 2–3 次；计划以 60–90 分钟 `phase` 为主 | 情报/知识快速变任务；被打断后第二天能接上 | C1、C4、C5 |
| R2 陈默 · 独立开发者 | 单项目长专注；工作流产出多；问答与知识沉淀多 | 产物/回答可归档，知识能变成下一步行动 | C2、C3、C4 |
| R3 周舟 · 备考学生 | 固定时段；`task` 型计划多；周末集中复盘 | 本周没做完的能顺延到下周，不丢任务 | C5、C4 |
| RX 跨角色 | 同时使用以上三类数据 | 防重复、空态、边界不串数据 | C6、C7 |

## 3. 执行方式

1. 每个场景记录：操作前数据量 → 操作 → 目标页可见 → API 字段 → 刷新后仍在 → 清理结果。
2. 手工路径 + CDP 断言：`window.api.listPlans()` / `listKnowledge()` 读取真实字段，不依赖截图判断。
3. 失败记录到 `docs/QA-ISSUES.md`，修复后回填场景状态。
4. 批量顺延、批量删除只在测试前置数据上执行，避免影响真实计划。
5. 优先级：P0 阻断主链路；P1 影响体验/一致性；P2 文案与边界。

### C8 跨 Agent 输入输出（20）

> 重点不是「按钮能点」，而是从外部 Agent 一侧确认：它实际收到了什么、回了什么，以及下游 Agent / 记录页看到的是不是同一份内容。
> 前置：Agent 页已注册可派发的 HTTP / CLI / MCP Agent；测试用本机回声 Agent 作为确定性的 I/O 探针。

### C9 参考产品输出 → 工作流编排（15）

> 目标：把其他产品（Trae / ZCode / Qoder / WorkBuddy 等）在本人场景下的真实输入输出，标记为参考样本，注入「一句话生成工作流」提示词。
> 边界：不是模型微调，而是提示词级 few-shot；参考只用于学习步骤划分 / 角色边界 / 信息组织，不照抄、不假设参考产品能力可用。
> 前置：C8 已完成，Agent 页有可派发的真实 Agent；参考样本存 `userData/agent-runs.json` 的 `reference` 字段，最多取最近 3 条成功且输出非空的记录。
