## 一、番茄钟完整联动系统

### 1.1 番茄钟全生命周期虚拟人行为

v2.3 已设计头顶倒计时环 UI，本节补全**虚拟人本体在番茄各阶段的行为变化**。

#### 阶段 A：番茄启动（0-3秒）

```
触发：用户开始番茄钟 / 自动从规划中启动 / 用户口头"开始专注"
```

| 时间 | 虚拟人行为 | 5性格差异 |
|------|-----------|----------|
| 0.0s | 虚拟人从当前姿态→挺直坐正（0.3s过渡） | ARIA: 精准坐正 / LUNA: 精神抖擞挺胸 / KIRA: 懒散→突然正经 / ZEN: 缓慢调整 / SHIN: 军人式立正 |
| 0.5s | 头顶倒计时环从0弧度增长到满弧（0.5s动画） | 统一 |
| 1.0s | 虚拟人进入对应工作状态（coding/writing/focus等） | 状态动画按v2.0规格 |
| 1.5s | 弹出气泡确认语（2秒后自动消失） | ARIA: "番茄25min开始。计时。" / LUNA: "加油哦！25分钟冲刺！(≧▽≦)" / KIRA: "行，25分钟。别让我抓到你摸鱼(╬▔皿▔)" / ZEN: "顺其自然，专注吧~" / SHIN: "番茄启动。预计产出：1个任务单元。开始。" |
| 3.0s | 气泡消失，虚拟人完全进入工作循环 | — |

#### 阶段 B：番茄进行中（3秒 ~ 倒计时结束）

虚拟人保持对应工作状态动画（v2.0规格），但增加番茄特有的微行为：

| 剩余时间 | 虚拟人微行为 | 头顶环状态 |
|---------|-------------|-----------|
| >15min | 正常工作动画，偶见抬头看环（确认时间） | 绿色满弧 |
| 10-15min | 微微加速动作（暗示节奏） | 绿色 60%-40% |
| 5-10min | 动作更专注，眉头微收 | 黄色 40%-20% |
| 3-5min | 开始整理姿态准备收尾，偶尔看环 | 黄色 20%-12% |
| 1-3min | 眉头收紧（冲刺感），动作加快 | 橙色 12%-4% |
| <1min | 极度专注表情，环红色闪烁 | 红色闪烁 4%-0% |

**性能感知降级**：animationLevel=medium 时跳过5min/3min/1min的微行为变化，仅保留环色变；minimal 时仅保留环色变。

#### 阶段 C：番茄完成（倒计时=0）

```
触发：倒计时归零
```

| 时间 | 虚拟人行为 | 5性格差异 |
|------|-----------|----------|
| 0.0s | 虚拟人停止工作动画，身体后仰放松（0.3s） | 统一后仰 |
| 0.3s | 头顶环消失（0.2s缩放淡出） | — |
| 0.5s | 虚拟人做"完成"表情+伸展动作 | ARIA: 满意微点头 / LUNA: 双手举起欢呼(≧▽≦)♡ / KIRA: 摊手"就这？"(≡▽≡) / ZEN: 伸懒腰~ / SHIN: 立正敬礼"任务完成" |
| 1.0s | 弹出休息选择面板（glass-card 240×120） | — |

休息选择面板：
```
┌─────────────────────────────────┐
│  ✅ 番茄完成！工作了 25:00      │
│  专注度：92%                    │
│                                 │
│  [休息5分钟]  [继续下一个]  [跳过] │
└─────────────────────────────────┘
```

#### 阶段 D：休息期间（选择"休息5分钟"）

| 时间 | 虚拟人行为 |
|------|-----------|
| 0.0s | 虚拟人从工作姿态→休息姿态（0.5s过渡，参考v2.0 break状态） |
| 0.5s | 虚拟人拿出隐形咖啡杯/伸懒腰/靠椅背 |
| 全程 | 头顶显示休息倒计时环（蓝色，反向：从0增长到满弧） |
| 休息中 | 虚拟人做放松微动画（每5s深呼吸一次，肩部起伏） |
| 休息结束 | 环满弧变绿闪烁，虚拟人坐直，弹出"休息结束，继续吗？" |

#### 阶段 E：番茄中断（用户手动停止）

```
触发：用户点击停止 / 关闭番茄 / 切换到非工作状态超过2分钟
```

| 中断类型 | 虚拟人反应 | 5性格差异 |
|---------|-----------|----------|
| 用户主动停止 | 虚拟人停下→看用户→气泡 | ARIA: "番茄中断。已工作12:34。记录。" / LUNA: "累了吗？休息一下也好♡" / KIRA: "又放弃了？才12分钟啊(╬▔皿▔)" / ZEN: "随心~" / SHIN: "中断记录。效率损失评估中。" |
| 摸鱼超2min自动中断 | 虚拟人从工作态→震惊→生气 | ARIA: "检测到摸鱼。番茄自动终止。" / LUNA: "啊...专注被打断了..." / KIRA: "哈！果然撑不住吧！我就知道！(￣▽￣)凸" / ZEN: "缘起缘灭~" / SHIN: "番茄失败。原因：自律不足。建议：重新开始。" |
| 会议打断中断 | 虚拟人理解→切换会议态 | 统一：无责备，平滑切换到会议状态 |

#### 阶段 F：连续番茄累积行为

| 连续数量 | 虚拟人累积行为 |
|---------|---------------|
| 2个 | 微笑加深，气泡"连续2个番茄！保持节奏" |
| 3个 | 虚拟人提醒"已连续3个，建议休息长一点（10min）" |
| 4个 | 虚拟人强制建议休息："第4个了！必须休息10分钟！" |
| 5个 | LUNA/KIRA/SHIN 强烈反对继续："5个了！你再不休息我挡屏幕！" → 触发轻度遮挡 |
| 6+个 | 强制休息模式：虚拟人遮挡30%屏幕，不允许继续番茄直到休息完成 |

### 1.2 番茄钟与情感系统联动

番茄完成时，虚拟人情感 PAD 值更新（参考 v2.4 情感系统）：

| 事件 | PAD 变化 | 合成情感 |
|------|---------|---------|
| 番茄完成（专注度>80%） | P+15, A+5, D+5 | 自豪 |
| 番茄完成（专注度50-80%） | P+8, A+0, D+3 | 满意 |
| 番茄完成（专注度<50%） | P+2, A+5, D-5 | 勉强满意 |
| 番茄中断（主动） | P-3, A-5, D-3 | 微遗憾 |
| 番茄中断（摸鱼） | P-10, A+10, D-8 | 失望/愤怒（KIRA强烈） |
| 连续3个番茄 | P+20, A+10, D+10 | 强自豪 |
| 连续5个番茄无休息 | P+5, A+15, D-5 | 担忧（怕用户过劳） |

### 1.3 番茄钟数据结构

```typescript
interface PomodoroSession {

  };
}
```

## 二、全局问答中虚拟人完整表现

### 2.1 Cmd+K 唤起时虚拟人行为序列

v2.3 定义了 Cmd+K 全局问答面板，本节补全**虚拟人在问答全流程中的表现**。

#### 阶段 1：唤起（用户按下 Cmd+K）

| 时间 | 虚拟人行为 | 说明 |
|------|-----------|------|
| 0.0s | 虚拟人当前工作动画暂停（不是停止，是"暂停帧"） | 保留当前姿态，动作冻结 |
| 0.2s | 虚拟人头部转向问答面板方向（屏幕中央偏上） | 0.3s平滑转头 |
| 0.5s | 虚拟人进入"聆听"姿态：身体微前倾、眼圆睁好奇、嘴微张 | 参考v2.0 AI问答状态 |
| 0.5s | 头顶当前状态指示器（番茄环等）降低透明度到0.3 | 避免干扰问答 |
| 0.8s | 答问面板从屏幕中央展开（glass-card 560×380） | v2.3规格 |

#### 阶段 2：用户输入中

| 状态 | 虚拟人行为 |
|------|-----------|
| 用户打字中 | 虚拟人微微点头（0.5s周期，幅度2°），表示"在听" |
| 用户停顿>2s | 虚拟人微歪头（好奇），但不催促 |
| 用户继续输入 | 恢复点头 |

#### 阶段 3：AI 思考中

| 时间 | 虚拟人行为 |
|------|-----------|
| 0.0s | 虚拟人切换到"思考"姿态：一手托腮、眼微眯、眉头微收 |
| 全程 | 头顶出现紫色思考粒子（3-5个小光点缓慢旋转） |
| 思考>3s | 虚拟人偶尔点头（似乎在"理解"什么） |
| 思考>8s | 虚拟人表情变认真，粒子加速旋转 |

#### 阶段 4：AI 回复中

| 时间 | 虚拟人行为 | 5性格差异 |
|------|-----------|----------|
| 0.0s | 虚拟人切换到"说话"姿态：面对用户、嘴部动画（开合同步）、手势 | — |
| 回复中 | 虚拟人做说话手势（一手展开比划），偶尔点头强调 | ARIA: 精准简短手势 / LUNA: 丰富表情手势 / KIRA: 随意摊手 / ZEN: 缓慢柔和手势 / SHIN: 干净利落军事手势 |
| 回复结束 | 虚拟人回到"等待"姿态：微微笑、看用户 | — |

#### 阶段 5：问答关闭

| 时间 | 虚拟人行为 |
|------|-----------|
| 0.0s | 问答面板收起 |
| 0.3s | 虚拟人头部转回工作方向 |
| 0.5s | 恢复之前暂停的工作动画（从暂停帧继续） |
| 0.5s | 头顶状态指示器恢复满透明度 |
| 0.8s | 完全恢复工作循环 |

## 三、虚拟人在各视图中的表现

### 3.1 设计原则

虚拟人不是独立于UI的——它会根据当前所在视图调整行为，仿佛"住在"这个页面里。

| 视图 | 虚拟人位置 | 虚拟人行为 | 与视图的联动 |
|------|-----------|-----------|-------------|
| 日历 | 右下角预设位 / 日历时间轴右侧 | 站在时间轴旁，手指当前时间点 | hover时间段→虚拟人指向该段；编辑时段→虚拟人做"记录"手势 |
| 监控 | 屏幕角落 / 监控面板旁 | 坐在小屏幕前看数据 | 当前状态变化→虚拟人同步切换状态；双屏异常→虚拟人转头看副屏 |
| 规划 | 待办列表旁 / 画布右侧 | 拿笔在列表旁做标记状 | 拖拽计划块→虚拟人做"调整"手势；完成项打勾→虚拟人点头 |
| 报表 | 报表右上角 / 图表旁 | 翻阅报告/指点图表 | 切换报表周期→虚拟人翻页动画；hover图表→虚拟人指向数据 |
| 桌搭 | 屏幕中央（展示位） | 站立展示/旋转预览 | 选择角色→虚拟人morph切换；切换场景→背景变换 |
| 设置 | 角落安静位 | 乖乖站好等配置 | 修改设置→虚拟人即时反映（如关遮挡→虚拟人做"解锁"手势） |

### 3.2 各视图详细行为规格

#### 日历视图（CalendarView）

```
默认位置：右下角预设位，但如果用户在编辑时间轴，
         虚拟人会走到时间轴右侧站立。

行为循环：
- 待机：站在时间轴右侧，偶尔指向当前时间线（垂直闪烁线）
- hover时间段：虚拟人转头看该段，手指指向它，
              头顶浮出mini tooltip "编码 45min"
- 编辑时段：虚拟人做"记录"手势（一手持隐形笔做标记）
- 拖拽时段：虚拟人做"移动"手势（双手做搬运动作）
- AI补录：虚拟人做"魔法"手势（一手举起，紫色粒子从手指飘出到时间轴）

特殊情况：
- 当天无计划：虚拟人坐在时间轴底部，气泡"还没有今天的计划哦"
- 摸鱼时段：虚拟人站在该红色段旁边，叉腰看着（提醒）
```

#### 监控视图（MonitorView）

```
默认位置：监控面板左下角，面向数据面板。

行为循环：
- 待机：坐在隐形椅子上看面板，偶尔点头（数据在更新）
- 状态切换：当前WorkState变化→虚拟人同步切换状态动画
- 双屏异常：副屏出现摸鱼→虚拟人头转向副屏方向，皱眉
- 专注度下降：专注度<50%→虚拟人表情变担忧
- 专注度上升：专注度>80%→虚拟人表情变自豪（微微笑）
- 查看轨迹条：用户hover轨迹条→虚拟人指向该时间点

主线/支线展示：
- 主线活跃：虚拟人面向主线面板
- 支线展开：虚拟人转头看支线详情
- 双线并行：虚拟人在两个面板之间来回看（巡视感）
```

#### 规划视图（PlanView）

```
默认位置：待办列表右侧 / 画布右下角。

行为循环（规划模式）：
- 待机：站在列表旁，一手持隐形笔
- 添加任务：虚拟人做"书写"手势（笔在列表上画）
- 拖拽排序：虚拟人做"搬动"手势
- 标记完成：虚拟人在该项旁画✓，点头
- Oner同步：虚拟人做"接收"手势（紫色数据流从右侧流入）

行为循环（执行模式）：
- 计划匹配：虚拟人站在计划块和实际轨迹之间，
            匹配时做✓手势，偏离时做⚠手势
- 摸鱼检测：实际轨迹偏离计划进入摸鱼→虚拟人表情变愤怒

行为循环（复盘模式）：
- 展示结果：虚拟人站在达成率大数字旁，做"展示"手势
- 归因分析：虚拟人指向失败项，做"分析"手势
```

#### 报表视图（ReportView）

```
默认位置：报表右上角。

行为循环：
- 待机：翻阅隐形报告，偶尔翻页
- 切换周期（日/周/月）：虚拟人做翻页动画
- hover图表：虚拟人指向数据点，头顶浮出数值
```

#### 学习 1：行为模式学习（用户对干预的反应）

```typescript
interface InterventionLearning {
```

## 八、通知系统统一规格

### 8.1 通知分级体系

v2.0-v2.4 中散落了各种通知机制（气泡/遮挡/弹窗/语音），本节统一规格。

| 级别 | 名称 | 视觉表现 | 虚拟人行为 | 声音 | 用户可消除 |
|------|------|---------|-----------|------|-----------|
| P0 | 静默 | 无 | 无 | 无 | — |
| P1 | 气泡 | 虚拟人头顶文字气泡（200×40） | 微表情变化 | 无 | 自动消失(5s)或点击 |
| P2 | 对话卡 | 虚拟人旁glass-card对话面板（240×120） | 虚拟人面对用户说话 | 低频语音 | 点击按钮选择 |
| P3 | 走过来 | 虚拟人走到屏幕中央+对话卡 | 虚拟人走到中央+手势 | 重要语音 | 必须选择按钮 |
| P4 | 遮挡 | 虚拟人+半透明遮挡层覆盖屏幕区域 | 虚拟人站在遮挡区+表情严肃 | 紧急语音 | 需满足条件才解除 |

### 8.2 通知类型映射

| 通知类型 | 默认级别 | 触发条件 | 升级条件 |
|---------|---------|---------|---------|
| 状态变化 | P0→P1 | WorkState切换 | 无 |
| 番茄完成 | P2 | 番茄倒计时=0 | 连续5个→P3强制休息 |
| 休息提醒 | P1→P2 | 连续工作50min | 连续90min→P3走过来 |
| 摸鱼提醒 | P1→P2→P3→P4 | 摸鱼5min | 15min→P2 / 30min→P3 / 60min→P4 |
| 会议即将开始 | P3 | 会议前10min | 前3min→P3走过来 |
| 加班确认 | P2→P3 | 预测下班时间已到 | 延后30min→P3再问 |
| 进度预警 | P2 | 进度落后>10% | 落后>25%→P3 |
| 任务完成 | P1 | 计划任务标记完成 | 无 |
| 深夜提醒 | P1→P2→P3 | 22:00/23:00/00:00 | 01:00→P3 |
| 健康提醒 | P2 | 喝水/久坐/眼休息 | 3次忽略→P3 |
| 系统通知 | P1 | 更新/错误/资源告警 | 严重错误→P2 |
| AI洞察 | P1 | AI分析出模式/建议 | 无 |
| 关系里程碑 | P2 | 7/30/100/365天 | 无 |

### 8.3 通知去重与队列

```typescript
interface NotificationQueue {
  pending: Notification[];
  active: Notification | null;    // 同时只显示1个P2+通知
  suppressed: Notification[];     // 专注时暂存的通知
}

// 去重规则
const dedupRules = {
  sameTypeCooldown: 300000,       // 同类型通知5min内不重复
  sameContentCooldown: 600000,    // 完全相同内容10min内不重复
  maxQueueSize: 5,                // 队列最多5条，超出丢弃最低优先级
};

// 专注时处理
function handleDuringFocus(notif: Notification) {
  if (notif.level >= P3) {
    // P3+通知即使专注也显示（会议提醒等）
    showNotification(notif);
  } else {
    // P1-P2暂存
    queue.suppressed.push(notif);
  }
}

// 专注解除后
function flushSuppressed() {
  // 合并同类通知
  // "离开期间：2条休息提醒、1条进度提醒"
  const summary = summarizeNotifications(queue.suppressed);
  if (summary.count > 0) {
    showSummaryBubble(summary);
  }
  queue.suppressed = [];
}
```

### 8.4 免打扰模式

| 模式 | 触发条件 | 通知行为 |
|------|---------|---------|
| 深度专注免打扰 | focus/coding >15min | 仅P3+通知，其余暂存 |
| 会议免打扰 | meeting状态 | 完全静默（P4除外） |
| 手动免打扰 | 用户在设置中开启 | 仅P4通知 |

## 十、虚拟人技术实现架构

### 10.1 渲染引擎选型

| 方案 | 引擎 | 优势 | 劣势 | 推荐度 |
|------|------|------|------|--------|
| A | Three.js + VRM | 生态成熟、VRM角色生态丰富、Web原生 | 性能一般、复杂着色器需手写 | ⭐⭐⭐⭐⭐ |
| B | Babylon.js + GLB | 性能好、物理引擎内置、PBR完善 | 角色生态不如VRM | ⭐⭐⭐⭐ |
| C | PixiJS + Spine | 2D骨骼动画、性能极好 | 不是3D、表现力有限 | ⭐⭐⭐ |
| D | 原生Canvas/SVG | 零依赖、极轻量 | 表现力差、动画开发量大 | ⭐⭐ |

**推荐方案：A — Three.js + VRM**

理由：
1. VRM 是 VTuber 标准格式，有大量现成高质量角色可用
2. Three.js 生态成熟，@pixiv/three-vrm 库可直接加载VRM
3. Electron 环境下 WebGL 性能可接受
4. cel-shading 可通过自定义 ShaderMaterial 实现
5. 用户可自行导入 VRM 角色（参考 Gatebox3/Desktop Mate 的角色自定义）

### 10.5 性能预算与降级

| 资源 | 预算上限 | 监控频率 | 降级触发 |
|------|---------|---------|---------|
| CPU | <5% (空闲时) / <8% (活跃时) | 每5秒 | >8% → 降一级 |
| RAM | <200MB | 每10秒 | >250MB → 清理粒子缓存 |
| GPU | <10% | 每5秒 | >15% → 降渲染级别 |
| 帧率 | 30fps (目标) / 15fps (最低) | 每秒 | <15fps → 降级 |

**降级链**：
```
full (全部动画+粒子+光环+高面数)
  ↓ CPU>8% or GPU>15% or FPS<25
medium (跳过微行为+粒子减半+光环降亮度)
  ↓ CPU>12% or GPU>20% or FPS<15
minimal (仅基础动画+无粒子+无光环+低面数)
  ↓ CPU>15% or GPU>25% or FPS<10
critical (静态姿态+最低渲染+无动画)
  ↓ 恢复条件满足
  ↑ 逐步恢复（每30秒升一级，直到稳定）
```
